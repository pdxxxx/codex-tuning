# 解除过度谨慎

Codex 有时会字面执行停止条件，为了无关的细节停下，或者每做一步都等确认。回复时做三件事：

1. 写清判定标准的本意；
2. 把后续步骤合并成一次连续执行；
3. 把停止条件收窄到真正需要人决定的情况。

## 因为无关差异停下

```
<结论>已经成立：<关键条件一致>，这就是我们要的结果。<列出的差异>与问题无关，不需要对齐，也不要再为此停下。
我之前写的"<原来的措辞>"，意思是 <本意>，不是 <它理解的意思>。

接下来连续完成 <步骤 A 到 B>，中间不要停下来等我确认：
1. <步骤>
2. <步骤>

只有以下情况才停下问我：<需要人决定的情况，最多三条>。
全部完成后，一次性给我：<交付物>。
```

## 因为来源不明的变更停下

先自己查清来源（`git diff`、文件修改时间），再给出明确的处置：

```
这份 <文件> 的改动不是其他会话做的：它的修改时间和 <另一个文件> 完全一致，是本会话中某次 <命令> 产生的，并且 <造成的后果>。

处理方式：
1. 执行 git checkout -- <文件> 还原，不要提交这份改动。
2. 之后 <正确的做法，例如只用 --frozen-lockfile 安装>；如果因此失败，报告出来，不要换用别的方式绕过。
3. 把 <根因> 记为一个独立问题，不在这次处理。

然后继续 <后续工作>。
```

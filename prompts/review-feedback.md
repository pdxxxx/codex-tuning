# 审阅反馈

先对照 `playbook/review-checklist.md` 审完规划，再选下面的一种回复。每条回复只给一个动作指令：要么"改完停下"，要么"改完继续"。

## 批准，但要先改几处

```
规划整体认可。先按以下几点修改 design.md 和 implement.md，只改受影响的段落，不要整体重写：
1. <问题>：<具体改法>。
2. <问题>：<具体改法>。
其余按规划执行。<改完停下给我看 | 改完直接 start 并实施>。
完成后逐条对照验收标准，附上命令和输出，做本地提交，不要 push。
```

## 否决一个方案

```
不采用 <方案>。原因：<一句话，例如"它绕过了服务方的明确限制"或"可以用 <原生机制> 代替">。
改为：<替代方案的要点>。
先修改 design.md，改完停下给我看，等我确认后再实施。
```

## 验收通过，交代下一步

```
<任务> 验收通过。<需要补的小事，例如提交某个同步修改、归档任务>。
然后 <下一步>。不要 push。
```

# 用真实请求调试线上问题

适用：靠读代码推断不出根因，或者推断反复出错的时候。核心是用实验代替推理：在本地复现，每次只改一个变量，设定预算，记录每次实验。

```
暂停修复方案，改为在本地用真实请求调试。目标是用实验证据回答两个问题，不要靠阅读代码推断：
① 问题由请求中的哪一部分引起；② 修复后，同一个请求能否成功。

## 环境
- 只在本机运行 <服务>，使用本地数据库；不连接、不修改线上服务。
- 需要真实凭据时，先问我从哪里来；未经我确认，不从线上复制任何凭据。
- 测试数据使用 <采集文件路径>。中间文件放在仓库之外（例如 <目录>），不提交，也不在回复中输出请求正文或凭据。

## 步骤
1. 复现：把最终发往上游的请求体落盘，用原始请求经本地服务发一次。错误码和关键参数与线上一致，就算复现成立；时区、时间戳、保活方式这类无关细节不需要对齐。
2. 对照：每次只改一个变量，其余保持一致；必要时二分，定位到具体的条目或字段。
3. 修复：根据实验结果做最小修复，再用原始请求经本地服务验证成功。不能只看状态码，要确认响应完整结束。
4. 补单元测试（不使用真实凭据），删除所有调试代码，跑完门禁。

## 约束
- 真实请求总数不超过 <N> 次；不要重复发送相同的无效请求。
- 每次实验记录：编号、改动的变量、请求体大小和 sha256、结果、耗时。
- 安装依赖时不改写锁文件。

## 只在以下情况停下
- 实验结果与当前假设矛盾，而且无法定位；
- 超出请求预算；
- 需要对线上做任何操作。

完成后一次性给我：实验表、修复的 diff、验证结果、门禁结果。
```

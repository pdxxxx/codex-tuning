# 审查 agent 写的仓库

适用：新接手一个主要由 agent 编写的仓库，或者长期由 agent 维护、感觉"越来越不像人写的"的仓库。可以发给 Codex，也可以发给另一个审阅用的 agent。

先生成体检报告：

```
python <codex-tuning>/tools/audit_repo.py <repo> > audit.md
```

```
请审查这个仓库中"人类工程师难以维护"的问题。只读，不修改任何文件。

先阅读 audit.md，再抽样阅读代码、项目 AGENTS.md、spec 和提交历史。重点找根源，不要逐行挑错：
- agent 读到的指导文本（AGENTS.md、spec、skill）是否本身就是问题来源：空模板、压缩文风、自造术语、写成变更日志的 spec；
- 包和目录的职责是否重叠、过碎；
- 命名是否充满没有出处的概念词，同一概念是否有多个名字；
- 超长函数集中在哪些核心路径；
- 测试是否按审查轮次组织；
- 提交粒度如何，仓库里有没有流水账、日志、二进制。

每个问题给出：严重程度、文件:行号和数字证据、建议的修法。同时列出做得好的地方。不确定的判断标注为假设。最后给出整改顺序的建议：先修指导文本，再加门禁，最后重构。
```

# 规格对照表

适用：规范已经写好，需要 Codex 证明每一条都做到了。光写"已自查"不可靠，要求它逐条抄录规范原文并附上证据。

在每个阶段的提示词末尾加上：

```
本阶段除了 manifest，还要在截图目录里提交 spec-check.md：
- 把 <规范文件> 中本阶段涉及部分的每一条要求原文抄过来，每条一行；本阶段用到的通用模式也要列进来。
- 每条后面填三项：是否符合（是 / 否 / 部分）、证据（截图文件名、命令输出或测试名）、不符合时的原因。
- "部分"只能用于"做了但没有完全验证"，要写清楚缺哪种证据。
- 不符合的条目不能自行换成别的做法。要么修正，要么列入"未解决"，等审阅决定。
- 汇报时先给出"否"和"部分"的数量，再列出所有"否"。
```

审阅时：

1. 先看"否"和"部分"，区分"真的有缺陷"和"只是没截图"。
2. 再抽几条"是"，打开对应的截图核对。如果对照表和截图对不上，说明这种自查方式也不管用，要换成你自己逐项核对。
3. 只是缺证据的条目，要求在下一阶段补齐；真正的缺陷，在审阅意见里逐条列出。

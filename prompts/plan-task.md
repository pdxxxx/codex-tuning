# 让 Codex 规划一个任务

适用：需求（prd）已经写好，让 Codex 写技术方案和执行计划，然后停下等审阅。下面以 Trellis 任务为例；不用 Trellis 的项目，把路径换成你的需求文档即可。

```
使用本仓库自己的 Trellis 运行环境（<repo>/.trellis）。

任务：.trellis/tasks/<task>（父任务：.trellis/tasks/<parent>）。

1. 先完整阅读父任务和本任务的 prd.md，以及 <相关 spec 或术语表>。
2. 进入规划：写 design.md 和 implement.md。只写决策和步骤，不写免责声明；design.md 不超过 120 行。写完停下来给我审阅，不要 start。
3. 内容必须来自现有代码和文档，并引用真实路径；不写通用套话。
4. 只修改 <允许的路径>。
5. 获批实施后：逐条对照验收标准，附上命令和输出；跑完 <门禁命令> 后做本地提交，不要 push。
```

可以按需加上：

- 需要先问我的事：`修改 <某文件> 之前，先把改动内容给我确认。`
- 依赖其他任务：`它依赖已完成的 <task>，必须使用 <产出物> 中的 <约定>。`
- 防止自建框架：`优先使用 <工具> 的原生机制，不要新建脚本、基线文件或框架。`
